# 性能观测速查

**先问「哪个资源、什么时间尺度、谁在消耗」**，再选工具。不要一开始就猜结论。

## 60 秒体检（Brendan Gregg 方法简化版）

| 顺序 | 命令 | 回答什么 |
|---|---|---|
| 1 | `uptime` | 负载（1/5/15 分钟趋势） |
| 2 | `dmesg \| tail -20` | 内核最近在说什么（OOM、磁盘错误） |
| 3 | `vmstat 1 5` | CPU/内存/换页/上下文切换 |
| 4 | `mpstat -P ALL 1 3` | 每核使用率（单核打满？） |
| 5 | `pidstat 1 5` | 哪个进程在吃 CPU |
| 6 | `iostat -xz 1 3` | 磁盘吞吐、延迟（`await`）、`%util` |
| 7 | `free -h` | 内存与缓存（看 `available`） |
| 8 | `sar -n DEV 1 3` | 网络吞吐 |
| 9 | `ss -s` | 连接数与状态分布 |
| 10 | `top` / `htop` | 综合实时观察 |

## 负载与 CPU

| 目的 | 命令 | 要点 |
|---|---|---|
| 负载趋势 | `uptime`；`cat /proc/loadavg` | 负载 ≈ 运行 + 不可中断的进程数 |
| 负载 vs CPU | `vmstat 1` 的 `r` 列与 `us/sy/id` | `r` 大 + `id` 高 → 可能在等 IO |
| 每核明细 | `mpstat -P ALL 1` | 区分「整体忙」与「一核打满」 |
| 进程排行 | `ps aux --sort=-%cpu \| head`；`pidstat -u 1` | 谁在消耗 |
| 线程级 | `top -H -p PID`；`pidstat -t -p PID 1` | 多线程程序的哪个线程 |

## 内存

| 目的 | 命令 | 要点 |
|---|---|---|
| 概览 | `free -h` | 看 `available` 与 `Swap used` |
| 换页 | `vmstat 1` 的 `si/so` | 持续非零 → 内存压力 |
| 进程内存 | `ps aux --sort=-rss \| head` | RSS 排序 |
| 泄漏线索 | `cat /proc/PID/status`（VmRSS） | 定时采样看是否单调上涨 |
| 缓存明细 | `slabtop`；`/proc/meminfo` | 内核对象占用 |
| OOM 记录 | `dmesg \| grep -i -E 'oom\|killed process'` | 谁被杀、当时内存多少 |

## 磁盘 IO

| 目的 | 命令 | 要点 |
|---|---|---|
| 使用率/延迟 | `iostat -xz 1` | `%util` 接近 100 且 `await` 上升 = 瓶颈 |
| 每进程 IO | `iotop -o`（需 root） | 谁在读写 |
| 打开的文件 | `lsof -p PID`；`lsof +D 目录` | 定位占用 |
| 文件系统空间 | `df -h`；`df -i` | 容量与 inode |
| 删除但仍占用 | `lsof +L1` | 释放需重启/重开进程 |

## 网络

| 目的 | 命令 | 要点 |
|---|---|---|
| 监听端口 | `ss -ltnp` | 谁在听、监听地址范围 |
| 连接统计 | `ss -s`；`ss -tan state established \| wc -l` | 连接数是否异常 |
| 流量 | `iftop`；`nload`；`sar -n DEV 1` | 实时与历史 |
| 抓包 | `sudo tcpdump -i any -nn port 80 -c 20` | 只看元数据也要小心隐私 |
| 连通与延迟 | `ping`；`mtr`；`curl -w '%{time_total}\n' -o /dev/null -s URL` | 分层定位 |

## 分析纪律

- **一次只改一个变量**：调整后重测，别同时换参数。
- **记录基线**：正常时也采样一次，才有「异常」的参照。
- **区分平均值与分布**：`await`、P99 延迟比平均值更能暴露问题。
- **结论要可复现**：留下命令、时间、输出，别人能重跑。
