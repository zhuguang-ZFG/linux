# 工具导航：按问题选工具

沿用知识库的分类入口，但不按热度堆工具。每项都说明要观察什么、如何验证，以及哪些结论不能由单个工具推出。

## 按任务的四类工具

| 任务 | 工具入口 | 验收方法 | 局限 |
|---|---|---|---|
| 看懂一条命令 | 本机 man、[tldr](https://tldr.sh)、[explainshell](https://explainshell.com) | 能逐个解释参数，再用临时数据验证 | 在线解释可能与本机版本不同 |
| 找文件和文字 | find、grep、sed、awk | 保存筛选前后的输入输出 | 文件名传递与文本行不是同一问题 |
| 检查脚本 | bash -n、[ShellCheck](https://www.shellcheck.net) | 语法/静态检查加失败路径测试 | 静态检查不能证明业务逻辑正确 |
| 查服务故障 | systemctl、journalctl、ss | 服务状态、日志与真实请求相互印证 | running 不等于用户请求成功 |
| 保存学习改进 | [Git](https://git-scm.com/book/zh/v2) | 提交能解释改动和验证方式 | Git 不自动清除已提交的秘密 |
| 复现应用环境 | [Docker](https://docs.docker.com/) | 构建、请求、重建、持久化都验证 | 镜像不等于运行中的全部数据 |
| 本地模型实验 | [Ollama](https://docs.ollama.com/docker)、[Open WebUI](https://docs.openwebui.com/getting-started/quick-start/) | CLI 与界面调用同一模型 | 运行成功不代表回答准确 |
| 认识真实硬件 | [实物图鉴](hardware-gallery.md) + lscpu/lsblk/lsusb | 实物、系统视图、任务需求能对应 | 外形不能证明兼容性 |
| 看懂数据流 | [动画实验室](visual-lab.md) | 先预测，再用命令复验 | 动画不是现场录像 |

## 按「认识阶段」分层的工具

同一个系统，可以从五个层次去看。**先想清楚自己在哪一层**，再挑工具：

| 层次 | 回答的问题 | 代表工具 |
|---|---|---|
| 命令层 | 这条命令怎么写、参数什么意思 | man、tldr、`--help`、type |
| 文件层 | 数据在哪个文件、什么内容 | ls、file、find、grep、awk、sed |
| 进程层 | 谁在运行、占了多少、和谁是父子 | ps、top、pstree、kill、pgrep |
| 服务层 | 服务在不在、日志说什么、端口谁在用 | systemctl、journalctl、ss |
| 系统层 | 整机负载、内存、磁盘与内核事件 | vmstat、free、df、dmesg、`/proc`、`/sys` |

**越往下越接近事实**：一个应用说「我好了」是进程层的信息，端口真的在听是服务层，而整机是否被拖垮要看系统层。多层次交叉印证，结论才站得住。

## 三条工具纪律

1. **先只读，再写入**：`ls`/`grep`/`ss`/`journalctl` 不会改变系统，`rm`/`chmod`/`iptables`/重启会。排障前期尽量停留在只读层。
2. **留证据再动手**：执行前记下「现在是什么样」（输出、退出码、时间），否则做完无法证明变好了。
3. **一个变量一次**：同时改三处再重启，成功也不知道是谁的功劳，失败更不知道是谁的锅。

## 三个常见场景的推荐链路

**场景一：磁盘看起来满了**

```text
df -h /              → 哪个文件系统满了（先看容量与 inode）
du -x -h --max-depth=1 路径 | sort -h   → 哪个目录最大
lsof +L1 2>/dev/null | head   → 有没有「已删除但被占用」的大文件
```

结论必须来自这三步的交叉，而不是直接删文件。

**场景二：服务起不来**

```text
systemctl status 服务名     → 状态与最近几行日志
journalctl -u 服务名 -n 50  → 完整错误上下文
ss -ltnp | grep 端口        → 端口是否已被别人占用
```

「配置改对了却起不来」经常是端口冲突或权限，而不是配置本身。

**场景三：网络通不通**

```text
ip -br address       → 有沒有地址
ip route             → 默认网关对不对
getent hosts 域名     → DNS 解析是否成功
curl -v 地址          → 连接、TLS 与响应逐层暴露
```

从链路层往上查：地址 → 路由 → 解析 → 连接 → 应用响应。

## 选择工具前的四个问题

1. 我需要解释、测量、修改还是保存？
2. 这个工具的输入是否含敏感信息，能否在本机完成？
3. 它会改变文件、权限、网络或服务状态吗？
4. 我用什么独立证据判断它做对了？

例如磁盘“满了”，先看 df 的容量和 inode，再看 du 与打开的已删除文件；不是先安装一款清理工具。工具选择要跟问题对应。
