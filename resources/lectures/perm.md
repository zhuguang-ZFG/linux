### 00:00 · chmod 644 之后，为什么连 cd 都进不去了

*开场 · 一个天天见的事故*

先看一个几乎人人踩过的事故。你听说权限要收紧，于是对一个目录敲了 chmod 六四四。文件倒是能打开，可 cd 进去，系统说权限不够。明明读权限还在，为什么连门都进不去？

画面要点：
- 权限收得干干净净
- 文件能打开，目录却进不去
- 问题出在那个 x

### 00:17 · 每个文件都登记三个归属问题

*世界观*

要讲清这个事故，先把世界观立起来。Linux 是多用户的：每个文件都登记三件事，所有者是谁，属于哪个组，其他人怎么办。还有一个超然的存在 root，用户号恒为零，能越过一切权限检查。日常干活用普通账号，需要时才借 root 的力。

画面要点：
- 谁是所有者 owner
- 哪个组 group
- 其他人 others 怎么办
- root 的 UID 恒为 0，能越过检查

### 00:40 · 先确认你是谁：三件套

*身份*

动手之前先确认你是谁。whoami 看名字，id 一条命令给出三样东西：用户号、初始组号、以及你所在的全部组。第三样最容易被忽略：只有当列表里出现 sudo 组，你才有资格使用 sudo。

画面要点：
- id 一条顶三样：UID、GID、组列表
- 看到 sudo 组，才说明你有资格借权

```bash
whoami
id
groups

# uid=1000(alice) gid=1000(alice)
#      groups=1000(alice),27(sudo)
```

### 00:58 · 一行 ls -l，藏着十个字符

*读 ls -l*

再看 ls -l 的那一列乱码。第一位是文件类型，短横是普通文件，d 是目录，l 是软链接。接着九位，每三位一组，分别是所有者、所属组、其他人的权限。再往后才是链接数、属主、属组、大小、时间和文件名。

| 位置 | 含义 | 例子 |
|---|---|---|
| 第 1 位 | 文件类型 | - 文件 / d 目录 / l 链接 |
| 2 到 4 位 | 所有者权限 | rw- |
| 5 到 7 位 | 所属组权限 | r-- |
| 8 到 10 位 | 其他人权限 | r-- |
| 后面 | 链接数 · 属主 · 属组 · 大小 · 时间 · 名字 | 1 alice dev 1024 notes.txt |

### 01:21 · 三位一组，按四二一加起来

*编码*

这九位为什么能写成三个数字？因为每一位有固定权重：读是四，写是二，执行是一。加起来就是一个数字。六等于四加二，读写。五等于四加一，读加执行。七就是全部。六四四，翻译回来就是 rw- r-- r--。

画面要点：
- r 是四，w 是二，x 是一
- 六等于四加二，读写
- 五等于四加一，读加穿过
- 七等于四加二加一，全部

### 01:46 · 同一个 x，文件和目录是两套语义

*关键分叉*

现在到了全片最关键的一处。同样是 x，对文件和目录完全不是一回事。对文件，r 是读内容，w 是改内容，x 是能执行。对目录，r 是能列出清单，w 是能创建删除条目，x 是能穿过去。目录没有 x，你连路径都走不通，有 r 也只能干看着。

画面要点：
- 文件：r 读内容，w 改内容，x 执行
- 目录：r 列清单，w 建删条目，x 穿过
- 目录没有 x，就算有 r，也进不去

### 02:12 · 亲手把门关上，再打开

*实验*

别急着背结论，亲手做一遍。建一个目录，里面放个文件，把目录改成六四四。cd 进去，被拒绝。可 ls 还能看到里面的文件，因为读还在。把目录改回七五五，马上又能进。你看，cd 失败不是文件没了，是路径上缺了穿过的那一位。

画面要点：
- cd 失败不是因为文件没了
- 是路径上缺了穿过的那一位
- chmod 755 补的就是 x

```bash
mkdir -p demo/inner
touch demo/inner/a.txt
chmod 644 demo
cd demo            # Permission denied
ls demo            # a.txt 还在
chmod 755 demo
cd demo            # 又能进了
```

### 02:36 · 目录 r 与 x 的四种组合

*组合*

把目录的 r 和 x 排列组合，行为就全解释通了。只有 r，能看名单，进不去。只有 x，进得去，但列不出名单，前提是你已经知道文件名。r 加 x，能进能列，但不能建也不能删。三个位全开，目录这一层才算畅通，不过里面每个文件还受它自己的权限约束。

| 目录权限 | 能做什么 | 不能做什么 |
|---|---|---|
| r-- | 看到名字清单 | 进入、读文件内容 |
| --x | 进入并访问已知路径 | 列出清单 |
| r-x | 列清单 + 进去 | 创建删除条目 |
| rwx | 列清单 + 进去 + 建删条目 | 仍然受里面文件自身权限限制 |

### 03:03 · umask：出厂默认权限是被划掉的

*新建文件*

那新建文件的权限是谁定的？是 umask。它不是直接给权限，而是从基数里划掉几笔。文件基数六六六，目录基数七七七，umask 零零二 划掉其他人的写，于是新文件六六四，新目录七七五。改成零二七，就划掉组的写和其他人的全部，新文件六四零，新目录七五零。

画面要点：
- 文件基数 666，目录基数 777
- umask 002 划掉其他人的写
- 结果：文件 664，目录 775
- umask 027 划掉组写和其他全部

### 03:31 · umask 写进 bashrc 才算永久

*让默认值生效*

注意作用域。命令行里敲 umask 零二七，只影响当前这个 Shell，退出就恢复。要永久生效，把这一行写进你的 bashrc，再 source 一次。这也是权限问题里最常见的误会之一：改了没生效，多半是没写对地方。

画面要点：
- 临时改，退出即恢复
- 永久改，写进 ~/.bashrc 再 source

```bash
umask                 # 0002
umask 027             # 只影响当前会话
touch secret.txt
ls -l secret.txt      # -rw-r-----

echo 'umask 027' >> ~/.bashrc
source ~/.bashrc
```

### 03:51 · rwx 之外，还有三个特殊位

*特殊位*

九位之外还有三个特殊位，藏在 x 的位置上。SUID 让程序执行时临时获得属主身份，passwd 改密码靠的就是它。SGID 放在目录上，让新建文件自动继承目录的组，团队协作目录常用。sticky 放在共享目录上，谁都能建文件，但只能删自己的，斜杠 tmp 最后那个 t 就是它。

画面要点：
- SUID：执行时临时获得属主身份
- SGID：目录里新建文件继承组
- sticky：共享目录里只能删自己的
- /tmp 最后的 t，就是 sticky

### 04:18 · 两条命令，把例子找出来

*看清系统里的特殊位*

怎么在系统里认出来？看 passwd 的第一列，属主执行位是 s，不是 x，这就是 SUID。看斜杠 tmp，其他人执行位是 t，这就是 sticky。最后那条 find 能列出系统里所有 SUID 程序，安全加固章节还会用到它。记住，SUID 是钥匙，自制程序检查不严，就是提权漏洞。

画面要点：
- s 在属主 x 位：SUID
- s 在属组 x 位：SGID
- t 在其他人 x 位：sticky
- SUID 是钥匙，也是提权漏洞的入口

```bash
ls -l /usr/bin/passwd
# -rwsr-xr-x   s 就是 SUID

ls -ld /tmp
# drwxrwxrwt   t 就是 sticky

find / -perm -4000 -type f 2>/dev/null
```

### 04:46 · su 换个人，sudo 借一条

*借权*

要动系统文件，就得借权。su 是彻底换个人，输的是对方的密码，切过去之后全程都是对方。sudo 只借一条命令，输的是你自己的密码，而且只限名单里放行的命令。谁有资格借，写在 sudoers 里，改它必须用 visudo，因为 visudo 会做语法检查，直接改坏了会把自己锁在门外。

画面要点：
- su 输目标用户的密码，切过去全程是对方
- sudo 输自己的密码，只借这一条命令
- 谁有资格借，写在 /etc/sudoers
- 改 sudoers 必须用 visudo

### 05:13 · 九个位不够用时，上 ACL

*权限之外*

九位权限只能分三类人。要是只想让 bob 一个人读写，既不想把他拉进组，也不该放开其他人，就用 ACL。getfacl 看规则，setfacl 减 m 给 bob 读写。注意 mask 是所有 ACL 条目的生效上限，明明给了读写却写不进去，先看它。ls 减 l 末尾出现加号，就说明这个文件带了 ACL。

画面要点：
- 只想给 bob 一个人读写，又不想拉进组
- setfacl -m u:bob:rw report.txt
- mask 是生效上限，给了权限也可能被它压住
- ls -l 末尾出现加号，说明带 ACL

### 05:41 · 三个最常见的权限事故

*避坑*

三个高频事故。第一，图省事敲 chmod 减 R 七七七，等于拆掉围墙，网页目录被篡改十有八九是它干的，正确姿势是目录七五五、文件六四四。第二，chown 减 R 手一抖，整棵树换了主人，服务立刻读不了，先列出目标再决定范围。第三，目录缺 x，cd、cp、rm 会报出看着毫不相干的错，先补 x 再谈读写。

| 现象 | 真正的原因 | 正确做法 |
|---|---|---|
| chmod -R 777 | 图省事拆掉围墙，网页目录被篡改多半是它 | 目录 755、文件 644，归属不对用 chown |
| chown -R 手抖 | 整棵目录树换了主人，服务立刻读不了 | 先 find 列出目标，再决定范围 |
| 目录缺 x | cd、cp、rm 报出看似无关的错 | 先补 x，再谈读和写 |

### 06:13 · 权限报错的三步定位

*排查*

遇到权限报错，不要瞎试。三步定位：先 id 确认你是谁，再 namei 减 l 一次列出整条路径每一层的权限，最后看卡在哪一层。很多怪问题不是目标文件错了，而是路径中间某个目录缺了 x。把链条摊开，答案基本自己就出来了。

画面要点：
- 先确认身份，再确认目标
- 路径上每一层目录都要有 x
- namei 一次列出整条链

```bash
# 1. 我是谁？
id

# 2. 文件和路径各是什么权限？
namei -l /srv/app/data.txt

# 3. 卡在哪一层？
ls -ld /srv /srv/app /srv/app/data.txt
```
