### 00:00 · 删了文件，磁盘空间为什么没回来

*开场 · 运维夜里的经典怪事*

运维深夜里最经典的一件怪事：日志把磁盘写满了，你 rm 掉几百兆，df 一看，水位一动不动。于是开始怀疑 rm 没生效、怀疑文件系统坏了。先别急，大多数时候不是没删掉，而是删除这件事，比你想的晚。

画面要点：
- 几百兆日志，rm 掉了
- df 一看，水位不动
- 不是没删掉，是删除比你想的晚

### 00:20 · 磁盘、分区、文件系统，三层各管一段

*分层*

要讲清删除，先把分层搞清楚。最底层是磁盘，一块块设备。上面切分区，每个分区是一段范围。再上面是文件系统，它负责把一个个块组织成文件和目录。lsblk 用树状展示这三层，fdisk 减 l 看分区表。最后一步是挂载，只有挂上去，文件系统才出现在目录树里。

画面要点：
- 磁盘是块设备，分区是切出来的范围
- 文件系统负责把块变成文件和目录
- lsblk 看树，fdisk -l 看分区表
- 挂载才让文件系统出现在目录树里

### 00:48 · 文件的名字，只是一块门牌

*本质*

文件到底是什么？内容其实住在 inode 里：权限、大小、数据块的位置都记在它身上。你看到的名字，只是目录里的一条映射，指向 inode 号。所以一个 inode 可以挂好几个名字，这就是硬链接。删除时只拆掉一个名字，只有当名字全拆光、并且没有进程还开着它，空间才真正释放。

画面要点：
- 内容住在 inode 里：权限、大小、数据块位置
- 目录项把名字映射到 inode 号
- 一个 inode 可以挂多个名字（硬链接）
- 名字删光、也没人打开，空间才释放

### 01:15 · 三条命令，把名字和本体分开看

*看清 inode*

用三条命令把名字和本体分开。ls 减 l 减 i，第一列就是 inode 号。stat 把 inode 号、链接数、块数全列出来。再给同一个文件建一个硬链接，你会看到两个名字指向同一个 inode，链接数变成二。所以硬链接不是复制，它只是多挂了一块门牌。

画面要点：
- ls -i 第一列就是 inode 号
- Links 是挂在这个 inode 上的名字数
- 硬链接不是复制，是多挂一块门牌

```bash
ls -li notes.txt
# 131073 -rw-r--r-- 1 alice dev 1024 notes.txt

stat notes.txt
# Inode: 131073  Links: 1

ln notes.txt hard.txt
ls -li notes.txt hard.txt   # 同一个 inode，Links: 2
```

### 01:40 · 硬链接与软链接，删除时完全不同

*链接*

把两种链接摆在一起。硬链接是同一个 inode 的另一个名字，不能跨分区，一般也不能指向目录，删掉原名字内容还在，只是链接数减一。软链接本身是个独立小文件，内容是目标路径，可以跨分区、可以指向目录，但原文件一删，它就悬空，ls 里通常显示成红字。

| 对比项 | 硬链接 | 软链接 |
|---|---|---|
| 本质 | 同一 inode 的另一个名字 | 一个独立文件，内容是目标路径 |
| 跨分区 | 不可以 | 可以 |
| 指向目录 | 通常不可以 | 可以 |
| 删原文件 | 内容还在，链接数减一 | 链接悬空，变成红字 |
| inode 号 | 相同 | 不同 |

### 02:03 · 还有进程开着，空间就还不能还

*第一层原因*

现在解释第一层原因：进程还开着它。进程打开文件后，内核会保留一个引用。你 rm 掉名字，引用还在，inode 和数据块就不能回收。lsof 加 L1 专门列出这种已删除但还被打开的文件。找到那个进程，让它关闭文件或者重启，空间立刻回来。这也是删日志前先看谁在写的原因。

画面要点：
- 进程打开文件后，内核保留 inode 引用
- rm 只是拆名字，引用还在
- lsof +L1 能找到已删除但被占用的文件
- 重启或让进程关闭文件，空间立刻回来

### 02:32 · 三步抓住那个占着空间的进程

*定位*

定位只要三步。df 减 h 先确认是哪个文件系统满，别在错的盘上找。lsof 加 L1 过滤出已删除还被打开的文件，输出里会明确写着 deleted。最后重启持有它的服务，再 df 一次，空间就回来了。生产上更稳的做法是让日志轮转，而不是直接 rm 正在写的文件。

画面要点：
- df 先确认是哪个文件系统满
- lsof +L1 按已删除文件过滤
- 重启持有者是最快的释放方式

```bash
df -h /var
sudo lsof +L1 | head
# nginx 1234 root 5w REG 8,1 524288000 0 131073 /var/log/app.log (deleted)

sudo systemctl restart nginx
df -h /var        # 空间回来了
```

### 02:57 · 写文件先到内存，再慢慢落盘

*第二层原因*

第二层原因在写入侧。Linux 把空闲内存拿来当缓存，写文件先写进页缓存，内核再找机会落盘。所以 cp 一个大文件秒回，不代表已经写进 U 盘。拔盘前要 sync 或者 umount，让缓存刷下去。用 dd 测速时看到的瞬时速度，很多时候是内存速度，不是磁盘速度。

画面要点：
- 页缓存把空闲内存当写缓冲
- cp 秒回，不代表已经写进 U 盘
- 拔盘前 sync 或 umount
- dd 的瞬时速度是内存速度

### 03:24 · df 与 du 不一致的四种真相

*对不上*

df 和 du 对不上，是四个真相之一。du 小于 df，多半是已删除还被占用。df 满了但 du 找不到大目录，去看 inode 是不是用尽，海量小文件最典型。du 很大而 df 没变，可能是稀疏文件，逻辑大小不等于实际占用。两个都小、df 还是高，去查文件系统的保留块，ext4 默认留百分之五。

| 现象 | 原因 | 验证 |
|---|---|---|
| du 小于 df | 已删除但被进程占用 | sudo lsof +L1 |
| df 满、du 找不到大目录 | inode 用尽（海量小文件） | df -i |
| du 很大、df 没变 | 稀疏文件，逻辑大小不等于实占 | ls -ls 看块数 |
| 两者都小、df 仍高 | 文件系统保留块（ext4 默认 5%） | tune2fs -l \| grep -i reserved |

### 03:53 · 每条真相，都有一条命令

*验证*

每一条真相都有对应的命令。df 减 i 看 inode 用量。truncate 造一个逻辑一 G 的稀疏文件，ls 减 l 显示一 G，但 ls 减 ls 第一列的块数很少，du 也小。保留块用 tune2fs 减 l 查。记住，df 看的是文件系统分配，du 看的是目录内容占用，两者天然可以不一致。

画面要点：
- 先分清是块用尽还是 inode 用尽
- 稀疏文件用 ls -ls 看第一列
- 保留块属于文件系统，不属于目录

```bash
df -i /                 # inode 用量
truncate -s 1G sparse.bin
ls -l sparse.bin        # 1073741824
ls -ls sparse.bin       # 实际块数很少
du -h sparse.bin

tune2fs -l /dev/sda1 | grep -i reserved
```

### 04:19 · 挂载像盖一块布，原目录没被删

*挂载*

再看一个常被误会成删除的现象：挂载。往一个非空目录上 mount，原来的东西没有删，只是被盖住了。umount 把布掀开，原内容又出现。开机自动挂载写 fstab，设备名请用 UUID，不要用 sd 加字母，因为盘符会变。fstab 写错，轻则挂不上，重则进不了系统，改之前先备份。

画面要点：
- 往非空目录 mount，原内容被盖住
- umount 掀开布，原内容又出现
- fstab 用 UUID，别用 /dev/sdX
- 写错 fstab 可能进不了系统

### 04:46 · findmnt 一眼看清谁盖在谁上面

*看挂载*

查看挂载，findmnt 最直接，能看出谁盖在谁上面。lsblk 减 f 把文件系统类型和 UUID 一起列出来，blkid 单独查 UUID。写 fstab 时加 nofail，挂载失败也不至于卡住启动。这些细节，平时不出事；出事时就是救命的。

画面要点：
- findmnt 看挂载点与来源
- lsblk -f 看文件系统类型与 UUID
- nofail 让挂载失败也能启动

```bash
findmnt /data
lsblk -f
blkid /dev/sdb1

# /etc/fstab
UUID=xxxx-xxxx /data ext4 defaults,nofail 0 2
```

### 05:09 · LVM：把多块盘拼成一个池子

*LVM*

再补一层运维必须知道的：LVM。它把物理卷 PV 组成卷组 VG，再从卷组切逻辑卷 LV。好处是扩容灵活，空间不够时加盘、扩卷组、扩逻辑卷。注意顺序：先扩逻辑卷，再扩文件系统。xfs 只能扩不能缩，ext4 可以缩，但要先卸载。方向搞反，就是数据事故。

画面要点：
- PV 物理卷 → VG 卷组 → LV 逻辑卷
- 扩容先扩 LV，再扩文件系统
- xfs 只能扩不能缩
- ext4 可扩可缩，但缩要先卸载

### 05:39 · 四个能让你丢数据的动作

*避坑*

最后四个能让数据直接没的动作。第一，对整盘 mkfs，分区表一起没，动手前 lsblk 减 f 再看一遍。第二，fstab 写错，开机卡救援模式，先 mount 测试，加 nofail。第三，rm 正在写的日志，空间不释放还让进程报错，用 logrotate 或者 truncate。第四，LVM 顺序搞反，缩的时候先缩文件系统、再缩逻辑卷，扩的时候反过来。

| 动作 | 真正的问题 | 先做什么 |
|---|---|---|
| 对整盘 mkfs | 分区表和数据一起没 | 确认设备名，lsblk -f 再看一遍 |
| fstab 写错 | 开机卡在救援模式 | 先 mount 测试，加 nofail |
| rm 正在写的日志 | 空间不释放，进程还报错 | 用 logrotate 或 truncate |
| LVM 先缩文件系统 | 文件系统损坏 | 先缩 FS，再缩 LV；先扩 LV，再扩 FS |

### 06:13 · 在镜像文件里走完整流程

*实验*

不动真盘也能练。用 truncate 造一个两百多兆的镜像文件，直接在上面 mkfs 点 ext4，再 loop 挂载到 mnt 下的目录。df 能看到它，umount 再卸掉。挂载点、文件系统、块设备这三层，一次就摸清了。实验产物放临时目录，做完删掉。

画面要点：
- 不动真盘，也能练格式化与挂载
- 挂载点、文件系统、块设备三层都摸一遍
- 实验产物放临时目录，做完删掉

```bash
truncate -s 256M disk.img
mkfs.ext4 disk.img
mkdir -p /mnt/demo
sudo mount -o loop disk.img /mnt/demo
df -h /mnt/demo
sudo umount /mnt/demo
```

画面要点：

- df 不降，先找开着的进程
