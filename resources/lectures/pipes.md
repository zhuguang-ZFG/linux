### 00:00 · yes | head 之后，退出码为什么是 141

*开场 · 一个看起来像报错的数字*

先看一条人人都写过的管道：yes 接 head，取前三行。输出没问题，可你回头一查退出码，一百四十一。是不是出错了？不是。这个数字背后，是管道、缓冲区和信号三件事一起工作的结果。

画面要点：
- 命令跑成功了
- 退出码却不是零
- 不是报错，是下游先走了

### 00:19 · 一切皆文件，每个进程有三条标准流

*底座*

先立底座。Linux 说一切皆文件，进程启动时，内核给它开三条流：标准输入零号，标准输出一号，标准错误二号。默认都接在终端上。注意，一号和二号虽然都显示在屏幕上，却是两条独立通道。所谓重定向，就是命令启动前，Shell 把这些号码牌偷偷改接到别处。

画面要点：
- stdin 是 0，stdout 是 1，stderr 是 2
- 默认都接在终端上
- stdout 和 stderr 是两条独立通道
- 重定向的本质是换掉这些号码牌的去向

### 00:46 · 管道是内核里的一段缓冲区

*管道*

管道不是把两个命令按顺序跑，而是请内核创建一段缓冲区，把上游的标准输出接到写端，下游的标准输入接到读端，然后两个进程同时启动。上游写满就停，下游读空就等，数据单向流动，像一条传送带。所以你看到的输出顺序，不代表它们只能一个接一个。

画面要点：
- Shell 创建管道，把写端接给上游
- 把读端接给下游，两个进程同时跑
- 写满就停，读空就等
- 数据单向流动，像一条传送带

### 01:10 · 下游先走，上游收到 SIGPIPE

*141 的来历*

现在回到一百四十一。head 读够三行就退出，管道的读端关闭。yes 还在拼命写，内核就给它一个 SIGPIPE 信号，编号十三，默认动作是终止进程。进程被信号杀掉时，退出码等于一百二十八加信号编号，一百二十八加十三，正好一百四十一。所以这不是失败，是下游先走了，上游被正常停掉。

画面要点：
- head 读够三行就退出，读端关闭
- yes 还在写，内核递来 SIGPIPE
- 信号 13 的默认动作是终止进程
- 退出码 128 加 13，就是 141

### 01:39 · 把每一环的退出码分别取出来

*验证*

别光听，动手验证。yes 接 head，echo  dollar 问号，得到一百四十一。想单独看上游，用 PIPESTATUS 数组，第零个元素就是 yes 的退出码。再看一个更危险的例子：false 接 true，整体退出码是零。因为 dollar 问号只看最后一个命令，前面的失败被吞掉了。写脚本时，这正是事故的来源。

画面要点：
- $? 只反映管道最后一个命令
- PIPESTATUS 数组保存每一环
- 前一个失败、后一个成功，整体仍是 0

```bash
yes | head -n 3
echo $?                 # 141

yes | head -n 3; echo ${PIPESTATUS[0]}   # 141
false | true; echo $?   # 0   ← 失败被吞了
```

### 02:07 · pipefail：任意一环失败，整条就失败

*补救*

补救很简单：在脚本开头写 set 减 o pipefail。它的规则是，任意一环非零，整条管道就非零。需要精确知道哪一环，再读 PIPESTATUS。注意，set 减 e 不是万能的，它和管道、条件判断、命令替换的组合有很多坑，pipefail 才是管道这一层的正解。

画面要点：
- set -o pipefail 写进脚本开头
- 任意一环非零，整条管道非零
- bash 还可以读 PIPESTATUS
- 别用 set -e 假装解决一切

### 02:32 · 六个写法，各自接管哪条流

*重定向*

重定向六式，关键是看它接管了哪条流。大于覆盖，双大于追加，小于把文件接到输入。2 大于只收错误。2 大于 &1 是让二号变成一号的副本，顺序非常关键，必须写在大于之后。& 大于 是 bash 的合体简写，换到精简的 sh 可能不认。

| 写法 | 作用 | 容易错在哪 |
|---|---|---|
| > file | stdout 覆盖写入 | 原内容立刻清空 |
| >> file | stdout 追加 | 日志常用 |
| < file | 把文件接到 stdin | wc 不再显示文件名 |
| 2> file | 只把 stderr 写入 | stdout 仍在屏幕 |
| 2>&1 | 让 fd 2 跟随 fd 1 | 顺序必须写在 > 之后 |
| &> file | stdout 和 stderr 一起 | bash 专属，sh 可能不支持 |

### 02:56 · 两个只差一个位置的写法

*顺序*

看这两个只差一个位置的写法。大于 all 点 log，再 2 大于 &1，两条流都进文件。反过来，先 2 大于 &1，再大于 all 点 log，错误还在屏幕上。原因是重定向按从左到右执行：先复制当时的一号，再改一号的去向。顺序一反，复制到的还是旧的终端。记不住就先写大于，再写合并。

画面要点：
- 顺序反了，错误流还指着终端
- 先重定向 stdout，再合并 stderr
- 记不住就先用 &> 验证

```bash
cmd > all.log 2>&1    # 两条都进文件
cmd 2>&1 > all.log    # 错误还在屏幕

# 读法：先复制 fd，再改 fd 的去向
# 2>&1 写在后面，才复制到已经改好的 1
```

### 03:25 · tee 是三通，xargs 是翻译官

*中间件*

管道里还有两个常用中间件。tee 像水管的三通，一份数据同时写文件、继续往下游走，减 a 是追加。xargs 是翻译官，管道传的是数据流，但 rm、cp、kill 只吃参数，xargs 把上游每一行变成下游命令的参数。加减 P 四还能开四个进程并发，批量处理时很有用。

画面要点：
- tee 把一份数据同时给文件和下游
- tee -a 追加，不覆盖
- xargs 把文本行变成命令参数
- xargs -P 4 可以并发

### 03:52 · 统计排行榜的万能模板

*经典组合*

最经典的组合：切出登录 Shell，排序，去重计数，再按数字倒序，取前五。四步各有分工，顺序不能换：uniq 只合并相邻的重复行，所以必须先 sort。这个骨架能套在任何排行榜上：日志里访问最多的 IP、最常用的命令、最大的目录，都是先统计、再倒序、取前 N。

画面要点：
- 顺序不能换：先排序再去重
- uniq 只合并相邻重复行
- 任何 Top N 都是这个骨架

```bash
cut -d: -f7 /etc/passwd | sort | uniq -c | sort -nr | head -5

# sort      先排序，让重复行相邻
# uniq -c   去重并计数
# sort -nr  按数字倒序
# head -5   取前五
```

### 04:18 · 行缓冲与全缓冲：日志为什么延迟

*缓冲*

最后一个容易被忽略的机制：缓冲模式。输出到终端时通常是行缓冲，一行一刷，你能实时看到。一旦重定向到文件或管道，很多程序切成全缓冲，四 K 一次。这就是 tail 减 f 有时延迟出现的原因。想让程序不缓冲，用 stdbuf 减 oL，或者程序自带的 line buffered 选项。

画面要点：
- 终端里按行刷新，你能实时看到
- 重定向到文件或管道后变成全缓冲
- 4KB 一次，所以 tail -f 有时延迟
- stdbuf -oL 或程序自带的 line-buffered

### 04:46 · 五个管道与重定向的坑

*避坑*

五个高频坑。脚本失败却返回零，因为问号只看最后一环，用 pipefail。2 大于 &1 没生效，顺序写反。文件名带空格，xargs 默认按空白切，用减 0 配 find 减 print0。管道里的 cd 不影响外面，因为每段都在子 Shell 里跑。tail 减 f 延迟，是输出被全缓冲。

| 现象 | 真正的原因 | 正确做法 |
|---|---|---|
| 脚本明明失败却返回 0 | $? 只看最后一环 | set -o pipefail |
| 2>&1 没生效 | 顺序写反，复制了旧的 fd 1 | 先 > 再 2>&1 |
| 文件名带空格时 xargs 断了 | 默认按空白切分 | xargs -0 配 find -print0 |
| 管道里的 cd 不影响外面 | 每段管道在子 Shell 里跑 | 用子 Shell 或改写逻辑 |
| tail -f 日志延迟出现 | 输出被全缓冲 | stdbuf -oL / --line-buffered |

### 05:13 · 十分钟做一次真实统计

*实验*

最后做个十分钟实验。用 seq 和 awk 造一千行假日志，统计来源地址的 Top 三。然后打开 pipefail，故意让上游 false，看整条管道的退出码变成一。tee 把中间结果落盘，方便复盘。这套动作练熟，日志分析就不再靠猜。

画面要点：
- 先造数据，再统计，可比对结果
- 打开 pipefail 后，上游失败会被看见
- tee 让中间结果落盘，方便复盘

```bash
set -o pipefail

# 造 1000 行假日志
seq 1 1000 | awk '{print "10.0.0." ($1 % 8)}' > access.log

# Top 3 来源
a | sort | uniq -c | sort -nr | head -3

# 故意让上游失败
false | tee out.txt; echo $?   # 1
```
