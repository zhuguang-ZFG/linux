# 常见误解 30 条：先破再立

这些说法在学习群里高频出现，而且**多数「听起来对」**。每条给出真相与验证方式——请自己跑一遍，别只信本页。

> 用法：读到这里不要背结论，把「自己验证」栏的命令在测试环境里跑一次。能重现的真相才算你的知识。

## 文件与权限（1-7）

**1. `rm` 会把文件内容真正擦除**
真相：`rm` 只是删除目录项，inode 与数据块可能还在——被删除未覆盖的数据有恢复可能，因此**涉密文件不能靠 `rm` 清除**。
自己验证：`ls -li 文件` 记下 inode，删除后对比。
详见 [文件与目录操作](../docs/01-basics/01-文件与目录操作.md)

**2. `sudo` 是「以 root 运行一切」的万能钥匙**
真相：`sudo` 按 `sudoers` 规则授权**特定命令**，且默认要密码。它能干的事由策略决定；能不用 root 就不用。
自己验证：`sudo -l` 列出你被允许的命令。
详见 [用户与权限](../docs/01-basics/03-用户与权限.md)

**3. `chmod 777` 是修权限问题的标准解法**
真相：777 = 所有人可读写执行，等于**拆掉门锁**。正确做法是最小必要权限（谁需要、需要读还是写、范围多大）。
自己验证：给测试目录设 777 前后对比 `ls -ld`，再想谁多拿了权限。
详见 [用户与权限](../docs/01-basics/03-用户与权限.md)

**4. 扩展名决定文件类型**
真相：Linux 靠**内容**（`file` 命令读魔数）判断类型，扩展名只是给人和程序看的约定。
自己验证：把 `a.txt` 改名 `a.jpg`，`file` 仍显示文本。
详见 [高效求助](../docs/01-basics/08-高效求助-man与tldr.md)

**5. 文件名大小写无所谓**
真相：Linux 文件系统**区分大小写**，`Readme.md` 与 `readme.md` 是两个文件——Windows 迁移时最常见的坑。
自己验证：新建同名不同大小写的两个文件。
详见 [文件与目录操作](../docs/01-basics/01-文件与目录操作.md)

**6. `.` 开头的文件是「隐藏文件」，看不见就删不掉**
真相：点开头只是**约定**（默认不列出），`ls -a` 就能看到；删除与是否隐藏无关。
自己验证：`touch .test && ls -a`。
详见 [文件与目录操作](../docs/01-basics/01-文件与目录操作.md)

**7. 硬链接会占用两份空间**
真相：硬链接是**同一 inode 的多个名字**，只有最后的名字被删除后空间才可能回收。
自己验证：`ls -li` 看两个名字的 inode 号是否相同。
详见 [磁盘与文件系统](../docs/02-advanced/07-磁盘与文件系统.md)

## 进程与内存（8-13）

**8. `free` 显示的 free 很小说明内存不足**
真相：Linux 会把空闲内存用于**缓存**，判断要看的列是 `available`，不是 `free`。
自己验证：读一个 1GB 文件前后各跑 `free -h`，观察 `buff/cache` 与 `available`。
详见 [性能观测与调优](../docs/03-pro/01-性能观测与调优.md)

**9. `kill -9` 应该优先使用**
真相：`-9` 不给进程收尾机会（临时文件、锁、缓冲区都可能留下）；先 `TERM`，确认无响应再考虑 `KILL`。
自己验证：对一个写文件的测试进程依次用 TERM/KILL，比较留下什么。
详见 [进程管理](../docs/01-basics/06-进程管理.md)

**10. 进程号（PID）是固定的**
真相：PID 每次启动都变，脚本里硬编码 PID 迟早出错——用 `pgrep`/`systemctl` 按名字找。
自己验证：连续启动两次 `sleep 100`，对比 PID。
详见 [进程管理](../docs/01-basics/06-进程管理.md)

**11. 关闭终端就等于结束里面的程序**
真相：终端退出会给前台进程发 SIGHUP；但用 `nohup`、`disown`、`systemd` 或终端复用器（tmux）的进程会继续运行。
自己验证：`nohup sleep 60 &` 后关闭会话，重新登录查 `pgrep sleep`。
详见 [进程管理](../docs/01-basics/06-进程管理.md)

**12. 必须重装系统才能解决内存泄漏**
真相：先确认是「进程泄漏」还是「缓存正常占用」，用 `ps aux --sort=-rss`、`smem`、`/proc/PID/status` 定位真凶。
自己验证：找出 RSS 增长最快的进程，观察它是否随请求线性上涨。
详见 [性能观测与调优](../docs/03-pro/01-性能观测与调优.md)

**13. 多核机器上程序一定跑得快**
真相：单线程程序只用一核；加锁竞争的并发程序可能更慢。加速取决于**能否并行**。
自己验证：用 `time` 对比 `yes | head -n 1000000` 与多核并行的等价任务。
详见 [性能观测与调优](../docs/03-pro/01-性能观测与调优.md)

## 磁盘与存储（14-18）

**14. `df` 说没满，所以一定有空间**
真相：**inode 也会用尽**（海量小文件），`df -i` 才能看到；还可能是已删除但被占用的文件仍占空间。
自己验证：`df -i /`；再 `lsof +L1 | head`。
详见 [磁盘与文件系统](../docs/02-advanced/07-磁盘与文件系统.md)

**15. `du` 与 `df` 数字不一致说明工具坏了**
真相：两者统计对象不同——`du` 看目录占用，`df` 看文件系统分配；被删除但打开的文件、稀疏文件、保留块都会造成差异。
自己验证：创建 1GB 稀疏文件（`truncate -s 1G`），对比 `ls -l`、`du -h`、`df -h`。
详见 [磁盘与文件系统](../docs/02-advanced/07-磁盘与文件系统.md)

**16. 拔 U 盘可以直接拔**
真相：写入可能还在**页缓存**里，直接拔会损坏文件系统；先 `sync` 或 `umount`。
自己验证：拷贝大文件后立刻看 `mount` 输出，用 `sync` 前后观察磁盘写入。
详见 [磁盘与文件系统](../docs/02-advanced/07-磁盘与文件系统.md)

**17. `/dev/sda` 永远是我的系统盘**
真相：设备名取决于枚举顺序（插拔、控制器、云主机），脚本应使用 `UUID=`/`LABEL=`。
自己验证：`lsblk -o NAME,UUID,MOUNTPOINTS` 看真实映射。
详见 [实物认识硬件](../docs/01-basics/09-从实物认识Linux硬件.md)

**18. 固态硬盘不需要考虑寿命**
真相：SSD 有写入次数限制，频繁全盘重写、日志狂刷、无 TRIM 会加速损耗；监控与合理配置（`fstrim.timer`）仍有必要。
自己验证：`smartctl -a /dev/nvme0` 查看 `Data Units Written`。
详见 [磁盘与文件系统](../docs/02-advanced/07-磁盘与文件系统.md)

## 网络（19-23）

**19. `ping` 通就说明服务正常**
真相：`ping` 只证明 ICMP 可达；服务可能没启动、端口被防火墙挡、应用返回错误。要分层验证。
自己验证：`ping` 通的主机上 `nc -vz host 端口`。
详见 [网络基础与远程连接](../docs/02-advanced/08-网络基础与远程连接.md)

**20. 有 IP 地址就能上网**
真相：还需要**路由**（默认网关）、**DNS**、以及对端可达。四步缺一不可。
自己验证：依次 `ip -br address`、`ip route`、`getent hosts 域名`、`curl -v 地址`。
详见 [网络基础与远程连接](../docs/02-advanced/08-网络基础与远程连接.md)

**21. 关闭防火墙更安全更快排障**
真相：关掉只是让问题消失，不是解决；正确顺序是**看清规则再放行最小必要端口**，且改动可回退。
自己验证：`nft list ruleset` 或 `iptables -L -n -v` 看现状，再定点放行。
详见 [安全加固](../docs/03-pro/03-安全加固.md)

**22. 公网 IP 暴露服务端口是最简单方案**
真相：暴露面越大风险越高；优先 VPN/隧道（WireGuard、Tailscale）、反向代理与认证。
自己验证：先用 `ss -ltnp` 盘点监听端口，只对外保留必要服务。
详见 [个人云盘与内网穿透](../docs/04-projects/项目3-个人云盘与内网穿透.md)

**23. 端口号可以随便改**
真相：1024 以下端口需要特权；已注册端口（如 80/443/3306）改动会牵连配置、防火墙、客户端与安全组。
自己验证：`/etc/services` 查端口惯例，再核对你的服务实际监听。
详见 [网络基础与远程连接](../docs/02-advanced/08-网络基础与远程连接.md)

## Shell 与命令（24-27）

**24. `2>&1 > file` 与 `> file 2>&1` 效果一样**
真相：重定向**从左到右**生效——前者把 stderr 指向终端，会漏日志到屏幕。
自己验证：`{ echo out; echo err >&2; } 2>&1 > /tmp/t.txt` 看屏幕与文件各有什么。
详见 [管道与重定向](../docs/02-advanced/01-管道与重定向.md)

**25. 命令没有输出就是没执行**
真相：Unix 哲学「没有消息就是好消息」——`grep` 无匹配、`cp` 成功都静默；判断成败要看**退出码** `$?`。
自己验证：`grep xxx 不存在模式` 后立刻 `echo $?`。
详见 [grep 文本搜索](../docs/02-advanced/02-grep文本搜索.md)

**26. 管道会等前一个命令全部结束**
真相：管道是**流式**的，多个命令同时运行；这带来缓冲与 SIGPIPE 行为，也可能让日志交错。
自己验证：`ping -c 100 127.0.0.1 | head -3` 为何立刻结束？——`head` 退出后 `ping` 收到 SIGPIPE。
详见 [管道与重定向](../docs/02-advanced/01-管道与重定向.md)

**27. 用 `ls | xargs rm` 清理文件没问题**
真相：文件名含空格/换行时会被拆错，可能误删；用 `find -print0 | xargs -0` 或 `find -delete`。
自己验证：造一个带空格的文件名，观察 `ls | xargs` 的行为。
详见 [Bash 脚本编程](../docs/02-advanced/05-Bash脚本编程.md)

## 系统与服务（28-30）

**28. 服务 `running` 就代表能正常工作**
真相：`active (running)` 只说主进程在；要做**真实请求验证**、看依赖服务与日志。
自己验证：`systemctl is-active 服务` 后，再用 `curl`/`ss` 做一次端到端检查。
详见 [systemd 服务与日志](../docs/02-advanced/06-systemd服务与日志.md)

**29. 容器就是「轻量虚拟机」**
真相：容器**共享宿主内核**，隔离强度弱于虚拟机；内核漏洞、资源限制（cgroup）、设备访问都不同。
自己验证：容器内 `uname -r` 与宿主一致；`ps -ef` 看到的是被隔离的进程视图。
详见 [容器与虚拟化](../docs/03-pro/04-容器与虚拟化.md)

**30. 备份就是把文件复制到另一个文件夹**
真相：同一块盘上的副本不算备份（盘坏一起没）；备份要满足**多份、异地/异介质、可恢复验证**（3-2-1）。
自己验证：把备份目录删掉再尝试恢复，看看能不能真的恢复业务。
详见 [家庭服务器实战](../docs/05-raspberry-pi/05-家庭服务器实战.md)

## 三条元误解

- **「我是新手，报错一定是我操作问题」**：也可能是环境、版本、权限或硬件——[先确认环境](environment-matrix.md)。
- **「教程这么写，照抄就行」**：教程有版本前提；[错误索引](error-index.md) 帮你分辨「版本差异」与「操作错误」。
- **「能跑通就理解透了」**：跑通只是开始，能解释**为什么**跑通、**什么情况会失败**，才算掌握。
