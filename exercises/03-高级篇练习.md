# 阶段 3 · 高级篇练习

对应 [高级篇](../docs/03-pro/01-性能观测与调优.md)。

## 一、概念判断

1. load average 高一定是 CPU 不够：对 / 错？
2. 删除文件后，只要进程仍持有打开的描述符，就有机会从 `/proc` 恢复：对 / 错？
3. sshd 配置的 99 文件一定覆盖 00 文件：对 / 错？
4. Dockerfile 的 FROM 行可在末尾随意加 `# 中文注释`：对 / 错？
5. `trap ... EXIT` 能处理 `kill -9` 和断电：对 / 错？

<details><summary>答案与原因</summary>

1. 错，D 状态任务也计入负载，需结合 CPU 和 IO。
2. 对，但进程退出或关闭描述符后可能失去机会；它不是备份策略。
3. 错，多数字段先读取的值生效，要查看 sshd -T 的最终结果。
4. 错，这些注释会成为指令参数，应放到独立行。
5. 错，无法捕获 KILL 和断电，需要考虑遗留文件与锁的恢复。
</details>

## 二、实操验收

### A. 性能观察

在测试机开终端运行 `vmstat 1`，另一个终端运行 `yes > /dev/null &` 并记下 `$!`。观察 CPU 与 load 的变化，结束时用记录的 PID 停止压力。解释为什么单个 yes 不一定让多核机器满载。

### B. SSH 策略核对

完成 [安全加固](../docs/03-pro/03-安全加固.md)，同时提供：语法检查、有效配置、密钥登录成功、密码认证失败四项证据。保留旧会话直到验证结束。

### C. Docker 响应

从仓库根目录构建：

```bash
docker build -t linux-course-hello scripts/docker-hello
docker run -d --name linux-course-hello -p 127.0.0.1:8097:8000 linux-course-hello
curl --retry 5 --retry-connrefused --retry-delay 1 http://127.0.0.1:8097
docker rm -f linux-course-hello
```

预期响应是 `你好，来自容器！`，不是目录列表。解释 EXPOSE 和发布端口的区别。

### D. 自动化

把 [巡检脚本](../scripts/health-report.sh) 配成定时任务，日志写入自己的目录。确认任务实际执行时间，而不是仅检查 crontab 已保存。

临时归档写在 `/tmp`，最终文件放在另一块磁盘，`mv` 是否保证原子发布？

<details><summary>答案</summary>

不能。跨文件系统的 mv 通常需要复制再删除。要避免读到半成品，先在目标目录所在文件系统创建临时文件，完成校验后再改名；并发写入还需要额外的协调策略。
</details>
